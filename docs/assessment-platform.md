# خطة تشغيل منصة التقييم الأمني

هذه النسخة تضيف إلى SecScan مساحة لمهام الاختبار. ينشئ المسؤول مشروعًا ويحدد الأصول والتصريح، ثم يوثق المختبِر ما قاسه ويعتمده مراجع قبل التسليم. تتضمن مساحة المشروع فحوص إعدادات محددة وأدوات لاستيراد نتائج خارجية. يغطي الاختبار اليدوي ضوابط الأعمال التي يحددها العميل.

## تجربة محلية

من جذر المستودع وباستخدام Node.js 22 أو أحدث:

```sh
npm ci
npm run build
npm run serve
```

افتح العنوان المطبوع ثم **Assessment projects**. أنشئ مشروعًا بأصل واحد، ومرجع تصريح ووقت انتهاء. اختر الأصل ثم أضف حالة لها توقع قابل للمراجعة. سجّل الإصدار والسلوك المشاهد والدليل. يضيف المراجع تعليل القرار ومسؤول الإصلاح. بعد الإصلاح سجّل ملاحظة جديدة على نفس الحالة. اعتماد نتيجة مطابقة بعد إخفاق سابق يتطلب دليل مقارنة إيجابيًا. النتيجة المتعذرة تُبقي الخلل مفتوحًا. ينشئ **Publish snapshot** نسخة ثابتة باللغتين، وتصدر **Print / save PDF** النسخة المختارة من المتصفح. تظهر نصوص الأدلة بلغتها الأصلية.

يُحفظ المشروع في `~/.secscan/projects`، ويمكن اختيار مجلد خاص عبر `SECSCAN_PROJECT_DIR`. تحفظ كل عملية إصدارًا كاملًا مستقلًا. تعارض تحرير النسخة يعيد HTTP 409، ثم يراجع المستخدم أحدث نسخة قبل إعادة التعديل. يبقى مسار الفحوص القديم مستقلًا ويرتبط بالمشروعات عبر استيراد حزمة أدلته.

## ما يعمل في كل مجال

| المجال | المدخل وطريقة العمل | حد الاستنتاج |
|---|---|---|
| الويب وواجهات API | مستند OpenAPI 3 بصيغة JSON يخطط حالة لكل عملية محلية. حزمة أدلة SecScan تربط ملاحظات الفحص بالأصل. يجمع `node scripts/posture.mjs https://app.example.test` ترويسات استجابة HEAD ونسخة TLS المتفاوض عليها لأصل واحد. | تُراجع عمليات OpenAPI دون تنفيذها عند الاستيراد. قياس TLS يصف الاتصال الذي جرى فقط. أدخل الأصل بصيغة مطابقة لقيمة origin في الملف. |
| الشبكات والواي فاي | الأمر `node packages/cli/dist/secscan.js wifi` يصدر JSON عن الاتصال النشط. يقارن برنامج الخدمة المرجعية قياسين من داخل الشبكة ومن شبكة الضيف. | تفترض الأداة أن المشغّل وقف فعلًا في نقطة القياس المذكورة. فشل الاتصال أو نقص معلومات التشفير تعذّر في القياس. |
| AWS | الأمر `node scripts/s3-snapshot.mjs BUCKET` يقرأ إعدادات حظر الوصول العام لدلو واحد بهوية AWS محلية تملك GetBucketPublicAccessBlock. سجّل اسم الدلو كأصل. يستورد IAM مستند سياسة هوية JSON ويراجع السماح العام غير المشروط. | إعداد دلو واحد أو بيان سياسة واحد جزء من الصورة. راجع بقية السياسات والتفويضات لإثبات الصلاحية الفعلية. |
| الكود والتبعيات | يستورد SARIF 2.1.0 نتائج التحليل، وCycloneDX JSON ملاحظات الثغرات المرفقة. أضف مرجع الـcommit أو الإصدار في خانة السياق. | لا تتم إعادة تنفيذ أداة التحليل أو جلب قاعدة CVE أثناء الاستيراد. نتيجة الأداة تدخل المراجعة. |
| Android | اختر ملف AndroidManifest.xml نصيًا مفكوكًا من إصدار معروف. تقرأ الواجهة debuggable وusesCleartextTraffic وتوثق القيم الصريحة. | قيمة غير مصرح بها تعطي نتيجة متعذرة. الفحص الديناميكي يحتاج حالات وأدلة مستقلة. |
| iOS | اقرأ ملف Info.plist الخاص ببناء معلوم باستخدام `python3 scripts/apple-snapshot.py Info.plist`. استورد JSON بصيغة ios لتوثيق استثناءات ATS العامة والخاصة بالنطاقات. | النتيجة تصف الإعداد المعلن في الملف. السلوك الفعلي على الجهاز يحتاج قياسًا منفصلًا. |
| منطق الأعمال | حالات يدوية لأدوار وموارد يحددها المالك. يبقى الدليل والتوقع وإعادة الاختبار في نفس الحالة. | يستطيع المراجع إرجاع النتيجة، وتظهر نسبة التغطية حسب الحالات المخططة. |

### قياس عزل شبكة الضيف

على جهاز داخلي مملوك للعميل، اختر عنوان IPv4 الخاص بواجهة الخدمة. انسخ الرابط الذي يطبعه الأمر الأول. نفّذ القياس الثاني من الشبكة الداخلية والثالث من شبكة الضيف خلال ١٥ دقيقة، مع استمرار تشغيل الخدمة. اجمع ملفي JSON على جهاز واحد ثم استورد الناتج بصيغة isolation.

```sh
node scripts/reference-service.mjs serve 192.168.1.20
node scripts/reference-service.mjs measure "<reference-url>" internal > internal.json
node scripts/reference-service.mjs measure "<reference-url>" guest > guest.json
node scripts/reference-service.mjs compare internal.json guest.json > isolation.json
```

وصول الضيف إلى نفس الخدمة مع نجاح القياس المرجعي يُسجّل مخالفة للعزل المتوقع. المهلة وحدها لا تثبت سبب الحجب. يمكن للمختبِر إضافة قرار جدار الحماية ودليل المقارنة في حالة يدوية.

### إرسال قياس من جهاز داخلي

الأداة تعمل باتصال صادر إلى API المشروع. استخدم هوية مختبِر تمت إضافتها للمشروع، واحفظ التوكن في متغير البيئة SECSCAN_PROJECT_TOKEN. يظهر معرّف المشروع في صفحة المشروع. تقرأ الأداة الملف الذي يختاره المشغّل ولا تستقبل أوامر تشغيل من الخادم.

```sh
node scripts/push-evidence.mjs https://console.example.test PROJECT_UUID wifi office-ap measurement-01 wifi.json
```

## النشر لفريق

- استخدم نشر API الخاص بالفريق خلف HTTPS، واضبط PostgreSQL وطبّق `npm run db:generate -w @secscan/api` ثم `npm run db:migrate` ثم أعد البناء. يدعم مسار الفحوص القائم Redis والعامل المستقل. سجلات المشروع محفوظة باستخدام ترحيل AssessmentProject.
- استخدم هويات API مسماة أو موفر OIDC. للموفر اضبط SECSCAN_OIDC_ISSUER وSECSCAN_OIDC_JWKS وSECSCAN_OIDC_AUDIENCE وSECSCAN_OIDC_CLIENT_ID، وأضف العنوان الجذري للواجهة كعنوان عودة لعميل عام يدعم Authorization Code مع PKCE. اضبط SECSCAN_OIDC_SCOPE حسب الموفّر. تحتاج المنصة access token موقّعًا صالحًا لجمهور API المشروع. هوية عضوية OIDC هي قيمة issuer ثم # ثم sub. احفظ توكنات الإدارة خارج المرفقات.
- يملك المنشئ إدارة العضويات. يستطيع tester التخطيط والتوثيق، وreviewer اعتماد الأدلة ونشر التقارير، وreader القراءة. يُطلب تفويض مستقل للوصول إلى كل مشروع ومرفق. بقية واجهات الفحص القديمة لها إعدادات التصريح والمصادقة الخاصة بها.
- للمرفقات النصية المنقحة اضبط SECSCAN_EVIDENCE_BUCKET وAWS_REGION وهوية الخدمة المصرح لها بالقراءة والكتابة. يحدد SECSCAN_S3_ENDPOINT خدمة متوافقة خاصة. يفهرس المشروع المرفق بحسب بصمة المحتوى، ويسجل طلب الوصول قبل تسليم رابط صالح لدقيقة. حد الملف ٦٤ كيلوبايت. يزيل المنقّح أنماطًا محددة لترويسات المصادقة والكوكيز والتوكنات، ويراجع المختبِر المحتوى الحر قبل الإضافة.
- النسخ الاحتياطي المحلي يشمل مجلد المشروعات كاملًا، ويضاف مخزن المرفقات عند تفعيله. للنشر المشترك أوقف الكتابة مؤقتًا وخذ نسخة PostgreSQL ومخزن الأدلة في نفس نافذة النسخ. استعد إلى بيئة منفصلة، وافتح تقريرًا قديمًا وملحقاته قبل اعتماد النسخة.

## قبول الإصدار

| المهمة | الدليل المطلوب |
|---|---|
| الإعداد والبناء | تثبيت نظيف، بناء الحزم والواجهة وفحص الأنواع. |
| العزل والمراجعة | حسابان في مشروعين منفصلين، رفض الوصول بينهما، مراجعة حالتين ومعالجة تعديلين متزامنين. |
| إعادة التحقق | فشل ما زال قائمًا، إصلاح مع دليل مقارنة، ونتيجة متعذرة بعد فقد الجلسة. |
| التقرير | مقارنة أعداد النسخة العربية والإنجليزية ومراجعة طباعة PDF. يبقى التقرير المنشور ثابتًا بعد تسجيل ملاحظة جديدة. |
| التجربة الميدانية | قياسان من شبكتين فعليتين، ومزوّد الهوية ومخزن الأدلة الخاصان بالفريق، وبيانات مرجعية من عميل مصرح به. |
| التسليم التشغيلي | تجربة الاستعادة، وقياس زمن التنفيذ ونمو التخزين وسعة التزامن على حجم موثق. يعتمد الفريق مدة الاحتفاظ بالأدلة ويطبقها على قاعدة البيانات ونسخ الملفات والنسخ الاحتياطية. |

أول إصدار مخصص لفريق تجريبي. تختبر الملفات الآلية قواعد القرار والعزل والحفظ، ويُدوّن قبول الأجهزة والمزودين الفعليين بعد التجربة. تقاس الدقة على عينات موصوفة لكل ضابط. مسار الفحص السريع القديم يضع إعادة الفحص الخالية من الدليل في حالة inconclusive؛ إغلاق النتائج المراجَع يحدث داخل حالة المشروع.
